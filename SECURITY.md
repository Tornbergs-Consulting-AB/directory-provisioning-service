# Security reporting

Report suspected vulnerabilities privately to the repository owner. Do not include exploit details, credentials, production identifiers, private keys or sensitive logs in public issues.

When this project is published on GitHub, use **Security → Report a vulnerability** if private vulnerability reporting is enabled. If that route is unavailable, obtain a private contact through the maintainer's public profile before sending sensitive information. Public-release preparation must enable private reporting or document a verified private contact.

Provide the release version, affected component, prerequisites, a minimal synthetic reproduction and potential impact. Supply safe logs only. No response or remediation deadline is guaranteed; coordinated disclosure timing should be agreed rather than assumed.

This project has no guaranteed LTS/security-support period. Operators must assess advisories for the service, its dependencies, separately installed Java and WinSW, and their directory/platform. Customers can maintain a fork when needed.
