# Maintenance and support

Directory Provisioning Service is an independent open-source project maintained on a best-effort basis. There is no guaranteed response time, release schedule, support lifetime or SLA. A stable version identifies a release; it does not promise indefinite compatibility, updates or maintenance.

Customers are responsible for their deployment configuration, credentials, AD delegation, certificates, backups, monitoring, testing and update decisions. Source, tests and build instructions allow customers to maintain a fork or engage another developer.

Use the project's issue tracker, once published, for reproducible non-sensitive defects and improvement requests. Include the application version, Java/OS version, safe response and correlation ID, and redacted configuration/log excerpts. Never post credentials, authorization headers, private keys, production account data or unredacted payloads.

Paid consulting or development may be agreed separately. Only an explicit separate agreement creates a service commitment. The software licence and applicable law govern warranty and liability; this document does not modify the licence.
